Map your app with Floorplan

Ask Claude for a map of your app's code. You get every part, file and connection drawn on one page, each named in plain English.

Floorplan is made by Hayden Smith. It is free and open source (MIT licence).
github.com/haydenschmitty/floorplan. All credit to him; this page is just how I set it up.

What you need

  • Claude Code (desktop app or terminal) or Codex. It runs on the plan you already have; no API key.
  • Node.js 18 or newer. Check by typing node --version in a terminal. If it's missing, install it from nodejs.org.
  • Your project in a git folder. Floorplan reads the files git knows about.

1. Install it (once)

In any terminal:

claude plugin marketplace add haydenschmitty/floorplan
claude plugin install floorplan@floorplan

Then start a new Claude Code session. Plugins only load when a session starts. In VS Code, reloading the window does it (Ctrl+Shift+P → Developer: Reload Window).

Using Codex instead? Open Plugins → Add a marketplace, enter haydenschmitty/floorplan, and install Floorplan.

2. Make your map

  1. Open your project's folder in Claude Code.
  2. Ask: "Make me a floorplan of this app."
  3. Allow it to run its scripts when asked. A small app takes a few minutes; my app (about 500 files) took about three.
  4. The map opens in your browser.

3. Things to try on the map

  • Start here: a one-minute tour of the app.
  • Flows: step-by-step walkthroughs of what your app does.
  • The Ask bar: ask a real question, like "What happens when I tap Approve?" It reads your code and answers on the map. Then press Walk through and watch it step from card to card.
  • Health: a quick automatic check (very large files, keys written into code, open endpoints). Treat it as a first look, not a security audit.

Good to know

  • It doesn't change your code. It writes its own floorplan/ folder, which keeps itself out of git. After my run, git status showed nothing new.
  • At the end it asks whether future sessions should use the map. If you say yes, it adds a short note to CLAUDE.local.md, a personal file that also stays out of git.
  • If your server's routes are written in an unusual way, the map may not list them one by one. Mine didn't; everything else mapped fine.
  • After more work, just ask "update the floorplan". It only re-reads what changed.

Haz un mapa de tu app con Floorplan

Pídele a Claude un mapa del código de tu app. Obtienes cada parte, archivo y conexión dibujados en una sola página, cada uno con un nombre fácil de entender.

Floorplan es obra de Hayden Smith. Es gratis y de código abierto (licencia MIT).
github.com/haydenschmitty/floorplan. Todo el crédito es suyo; esta página solo cuenta cómo lo instalé yo.

Qué necesitas

  • Claude Code (la app de escritorio o la terminal) o Codex. Funciona con el plan que ya tienes; no necesitas una clave de API.
  • Node.js 18 o más nuevo. Para verificarlo, escribe node --version en una terminal. Si no lo tienes, instálalo desde nodejs.org.
  • Tu proyecto en una carpeta con git. Floorplan lee los archivos que git conoce.

1. Instálalo (una sola vez)

En cualquier terminal:

claude plugin marketplace add haydenschmitty/floorplan
claude plugin install floorplan@floorplan

Después abre una sesión nueva de Claude Code. Los plugins solo se cargan cuando empieza una sesión. En VS Code basta con recargar la ventana (Ctrl+Shift+P → Developer: Reload Window).

¿Usas Codex? Abre Plugins → Add a marketplace, escribe haydenschmitty/floorplan e instala Floorplan.

2. Haz tu mapa

  1. Abre la carpeta de tu proyecto en Claude Code.
  2. Pídele: "Hazme un floorplan de esta app."
  3. Dale permiso para correr sus scripts cuando te lo pida. Una app pequeña tarda unos minutos; la mía (unos 500 archivos) tardó unos tres.
  4. El mapa se abre en tu navegador.

3. Qué probar en el mapa

  • Start here: un recorrido de un minuto por la app.
  • Flows: recorridos paso a paso de lo que hace tu app.
  • La barra Ask: hazle una pregunta real, como "¿Qué pasa cuando toco Aprobar?". Lee tu código y responde sobre el mapa. Luego toca Walk through y míralo avanzar de tarjeta en tarjeta.
  • Health: una revisión automática rápida (archivos muy grandes, claves escritas en el código, endpoints abiertos). Tómalo como un primer vistazo, no como una auditoría de seguridad.

Bueno saber

  • No cambia tu código. Escribe su propia carpeta floorplan/, que se mantiene fuera de git sola. Después de usarlo, git status no mostró nada nuevo.
  • Al final te pregunta si las próximas sesiones deben usar el mapa. Si dices que sí, agrega una nota corta a CLAUDE.local.md, un archivo personal que también queda fuera de git.
  • Si las rutas de tu servidor están escritas de forma poco común, puede que el mapa no las liste una por una. Las mías no salieron; todo lo demás se mapeó bien.
  • Después de seguir trabajando, solo pídele "actualiza el floorplan". Solo vuelve a leer lo que cambió.
