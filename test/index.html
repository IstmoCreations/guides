Test an AI tool before you trust it

How I tested Meta's Astryx design system: three AI builders, the same three jobs, judged blind by a different AI. Here are the exact prompts and steps, so you can test any tool on your own work.

Astryx is Meta's open-source design system (github.com/meta/astryx, MIT licence, in beta). The judge was OpenAI's Codex. Not sponsored by either.

This is a small test, not a benchmark. One run per builder, one judge, first screens only. A different run could swap two close results. Astryx is built for big teams keeping hundreds of screens consistent, which one page can't test.

1. Pick three small, real jobs

Different kinds of screens, each one a single paste. These were mine:

Replace the starter page of this Vite + React + TypeScript app with this:
"A members dashboard for a small paddling club. Top: club name 'Bahía Paddle Club' and today's date. A row of four headline numbers: active members (48), sessions this week (12), payments due (5), boat racks free (3). Below: the next five sessions (day, time, coach, spots left), and a members table (name, plan, last session, payment status shown as a badge) with a search box. It should look polished and modern, like a real product, on a laptop screen."
Use made-up data (8-10 members). Single page, no routing, no backend.
Replace the starter page of this Vite + React + TypeScript app with this:
"A landing page for 'Ola Negra', a small surf and paddle retreat on Panama's Pacific coast. Dark, bold, editorial style: big confident type, a strong hero with a headline and a 'Book your week' button, a short 'what a day looks like' section (dawn paddle, surf lesson, long lunch, sunset session), three retreat packages with prices ($890 / $1,290 / $1,990 per week) where the middle one is highlighted, two guest quotes, and a footer. It should feel premium and memorable, not like a template, on a laptop screen."
No images available: use colour, type, shapes and CSS only. Single page, no routing, no backend.
Replace the starter page of this Vite + React + TypeScript app with this:
"A phone app screen for 'Coco', a friendly AI assistant that helps a small café owner. Mobile-first, designed for a 390 x 844 phone screen. Warm, playful, friendly style. A top bar with Coco's name and avatar, a chat with 6 made-up messages, a typing indicator, and a message composer pinned at the bottom with an attach button and a send button. It should look like a real, polished app."
No images: use emoji, colour, type and CSS only. Single screen. Sending a typed message should append it to the chat.

2. Run each job with and without the tool

Same AI, same model, a fresh copy of the same starter project each time. Add one line per builder. With the tool:

This app has Meta's Astryx design system installed, with its CLI. Run the CLI's build command with no arguments first, read its playbook, and follow it. You may install any Astryx package and anything an Astryx template says it needs. Install nothing else. Finish when the build passes, and report anything confusing or broken.

Without it: Build it with plain React and your own CSS. Do not install any packages.

Make "plain" really plain. Claude Code normally loads your skills, plugins and instruction files. To switch them off (Claude Code CLI), save this as bare-settings.json, with the first line changed to the full path of your own user CLAUDE.md (Windows: C:/Users/you/.claude/CLAUDE.md, Mac: /Users/you/.claude/CLAUDE.md). The second line covers every project's CLAUDE.md.

{"claudeMdExcludes": [
  "C:/Users/you/.claude/CLAUDE.md",
  "**/CLAUDE.md"
]}

Then run each plain job from its own project folder:

claude -p "<the job prompt>" --setting-sources project --settings bare-settings.json --disable-slash-commands --strict-mcp-config --no-session-persistence --output-format json

Check it worked before you trust it: ask the same command "List every skill and any CLAUDE.md instructions in your context, or say NONE". It should say NONE. Then remove the settings file and ask again: now it should list them. If both answers match, the switch did nothing.

3. Screenshot, then hide the names

Take the first screen of each result at the size it was made for (laptop or phone). Rename the three files of each job to X, Y and Z in a random order, and write the key down somewhere the judge can't see.

4. Ask a different AI to judge blind

Attach the screenshots and paste this. Using a different company's model means it has no reason to favour its own work.

You are an independent design judge. Everything you need is in this message and the attached screenshots. Do not browse or read files.
Three separate AI runs built each interface from the SAME brief. For each job the results are labelled X, Y, Z in random order (the letters mean nothing and are shuffled per job).
[Paste each job's brief here.]
Before judging, state in two sentences your own criteria for "good".
1. For each job, rank X, Y, Z from best to worst and score each 1 to 10 for: visual polish, fit to the brief, distinctiveness (designed, not a default template), and readability at that screen size. Name any visible defect.
2. Is any one approach consistently stronger or weaker? Only say so if the screenshots support it.
3. Mark each claim VERIFIED (visible) or ASSUMED, and list what the screenshots did not let you judge.
End with one line per job: JOB 1: best=<letter> middle=<letter> worst=<letter>

5. Unblind, and count the cost too

Match the letters back with your key. Then compare what each builder cost you: how long it took, and how much code it shipped (the size of the built files). A tool can look the same and still cost more.

Prueba una herramienta de IA antes de confiar en ella

Cómo probé Astryx, el sistema de diseño de Meta: tres constructores de IA, los mismos tres trabajos, juzgados a ciegas por otra IA. Aquí están los prompts y pasos exactos, para que pruebes cualquier herramienta con tu propio trabajo.

Astryx es el sistema de diseño de código abierto de Meta (github.com/meta/astryx, licencia MIT, en beta). El juez fue Codex, de OpenAI. Sin patrocinio de ninguno.

Es una prueba pequeña, no un benchmark. Una corrida por constructor, un juez, solo la primera pantalla. Otra corrida podría invertir dos resultados cercanos. Astryx está hecho para equipos grandes que mantienen cientos de pantallas iguales, algo que una sola página no prueba.

Puntaje a ciegas sobre 120: mi configuración 104, IA sola 102, Astryx 73. Mi configuración tardó de 2 a 5 veces más que la IA sola. Las páginas con Astryx pesaban unas 4 veces más código.

1. Elige tres trabajos pequeños y reales

Pantallas de distinto tipo, cada una en un solo mensaje. Usé los de arriba en inglés (cambia a English para copiarlos); funcionan igual traducidos.

2. Corre cada trabajo con y sin la herramienta

La misma IA, el mismo modelo, una copia nueva del mismo proyecto inicial cada vez. Agrega una línea por constructor. Con la herramienta:

Esta app tiene instalado Astryx, el sistema de diseño de Meta, con su CLI. Primero corre el comando build del CLI sin argumentos, lee su guía y síguela. Puedes instalar cualquier paquete de Astryx y lo que una plantilla de Astryx diga que necesita. No instales nada más. Termina cuando el build pase, e informa lo que haya sido confuso o no haya funcionado.

Sin ella: Hazlo con React y tu propio CSS. No instales ningún paquete.

Que la IA "sola" esté realmente sola. Claude Code normalmente carga tus skills, plugins y archivos de instrucciones. Para apagarlos (Claude Code en la terminal), guarda esto como bare-settings.json, cambiando la primera línea por la ruta completa de tu propio CLAUDE.md de usuario (Windows: C:/Users/tu-usuario/.claude/CLAUDE.md, Mac: /Users/tu-usuario/.claude/CLAUDE.md). La segunda línea cubre el CLAUDE.md de cada proyecto.

{"claudeMdExcludes": [
  "C:/Users/you/.claude/CLAUDE.md",
  "**/CLAUDE.md"
]}

Luego corre cada trabajo sin herramienta desde su propia carpeta:

claude -p "<el prompt del trabajo>" --setting-sources project --settings bare-settings.json --disable-slash-commands --strict-mcp-config --no-session-persistence --output-format json

Comprueba que funcionó antes de confiar: pregúntale con el mismo comando "Lista cada skill y cualquier instrucción de CLAUDE.md en tu contexto, o di NONE". Debe decir NONE. Luego quita el archivo de configuración y pregunta otra vez: ahora debe listarlos. Si las dos respuestas son iguales, el interruptor no hizo nada.

3. Captura la pantalla y oculta los nombres

Toma la primera pantalla de cada resultado al tamaño para el que se hizo (laptop o teléfono). Renombra los tres archivos de cada trabajo como X, Y y Z en orden al azar, y anota la clave donde el juez no pueda verla.

4. Pídele a otra IA que juzgue a ciegas

Adjunta las capturas y pega esto. Usar un modelo de otra empresa significa que no tiene motivo para favorecer su propio trabajo.

Eres un juez de diseño independiente. Todo lo que necesitas está en este mensaje y en las capturas adjuntas. No navegues ni leas archivos.
Tres corridas de IA distintas construyeron cada interfaz con el MISMO encargo. Para cada trabajo los resultados se llaman X, Y, Z en orden al azar (las letras no significan nada y se mezclan en cada trabajo).
[Pega aquí el encargo de cada trabajo.]
Antes de juzgar, di en dos frases tus propios criterios de "bueno".
1. Para cada trabajo, ordena X, Y, Z de mejor a peor y califica cada uno de 1 a 10 en: acabado visual, ajuste al encargo, personalidad (diseñado, no una plantilla por defecto) y legibilidad a ese tamaño de pantalla. Nombra cualquier defecto visible.
2. ¿Algún enfoque es siempre más fuerte o más débil? Dilo solo si las capturas lo respaldan.
3. Marca cada afirmación como VERIFICADO (visible) o SUPUESTO, y lista lo que las capturas no te dejaron juzgar.
Termina con una línea por trabajo: TRABAJO 1: mejor=<letra> medio=<letra> peor=<letra>

5. Revela los nombres, y cuenta también el costo

Empata las letras con tu clave. Luego compara lo que te costó cada constructor: cuánto tardó y cuánto código entregó (el peso de los archivos compilados). Una herramienta puede verse igual y aun así costar más.
